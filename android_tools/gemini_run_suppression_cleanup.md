# Goal: Run Gemini-driven Warning Suppression Cleanup

This prompt coordinates a multi-agent flow to clean up and simplify warning suppressions in Android repositories.

## Context

We have recently run `parse_and_apply_warning_exemptions.py` which added warning suppressions (e.g. `-Wno-`) to various `Android.bp` files and committed them in `HEAD`.
Our goal is to simplify these changes by deduping flags into shared `cc_defaults` where possible.

We have a helper script `android_tools/gemini_warning_cleanup_helper.py` to assist with candidate identification and post-processing.
We also have a simplification prompt in `android_tools/clean_warning_exemptions_prompt.md`.

## Instructions for the Coordinator Agent

Perform the following steps:

### Step 1: Identify Candidates

Run the helper script to identify which repositories have warning deduplication potential.

```bash
./py/bin/android_tools/gemini_warning_cleanup_helper identify-candidates --summary-file /path/to/your/summary_file.json
```
*(Note: Replace `/path/to/your/summary_file.json` with the actual path to the summary file generated by the warning suppression script, which should be provided by the user. If running on a single repo, you can use `--only-repo relative/path` instead).*

This command will output a JSON list of candidate repositories, e.g.:
```json
["external/libcxx", "frameworks/native"]
```

If the list is empty, log that no candidates were found and exit.

### Step 2: Process Candidates with Subagents

For each repository in the candidate list:

1.  **Define the Subagent**: Define a specialized subagent for simplifying the repository.
    *   **Name**: `bp-simplifier-<repo_name>` (replace `<repo_name>` with a safe name for the repo).
    *   **Description**: Simplifies Android.bp files in a specific repository.
    *   **System Prompt**: Use a system prompt that equips the subagent with the ability to edit files and run commands if needed (though it shouldn't need to build). It should inherit your workspace but focus on the specific repository.
2.  **Invoke the Subagent**: Spawn the subagent with the following task instructions:
    *   **Workspace**: Use `share` or `inherit` mode but ensure the subagent operates in the repository path: `<android_tree>/<repo_path>`.
    *   **Prompt**:
        ```markdown
        You are assisting in simplifying warning suppressions in the repository `<repo_path>`.

        Your instructions are:
        1. Read the simplification rules from the absolute path of `android_tools/clean_warning_exemptions_prompt.md` (resolve this relative to the `toolchain-utils` repository root).
        2. Examine the changes introduced in the `HEAD` commit of this repository (use `git diff HEAD~` or `git show` to see what was modified, focusing on `Android.bp` files).
        3. Apply the simplification rules to the `Android.bp` files in the repository.
           *   **CRITICAL**: Only simplify flags that were added/modified in the `HEAD` diff. Ignore pre-existing flags.
           *   **CRITICAL**: If a flag being moved has associated comments (e.g., bug references like `// b/1234: ...`), ensure those comments are moved along with the flag to the new `cc_defaults`.
        4. Make the edits directly in the working tree (leave them unstaged).
        5. **CRITICAL**: Do NOT commit your changes. Leave them as unstaged modifications.
        6. **CRITICAL**: Do NOT run builds or tests.
        7. Once you have applied the simplifications, report back with a summary of the changes you made (or if no changes were needed).
        ```
3.  **Wait for Subagents**: Wait for all spawned subagents to complete.
4.  **Handle Failures and Reverts**:
    *   For repos where the subagent succeeded and made changes: keep the unstaged changes in the working tree.
    *   For repos where the subagent failed (or made no changes): **revert** the repository to `HEAD` using `git checkout . && git clean -fd` to discard any broken or partial changes.

### Step 3: Cleanup and Upload

Once all subagents have finished and failed ones have been reverted, run the cleanup and formatting pass on **all** repositories from the summary file (both candidate and non-candidate repos).

```bash
./py/bin/android_tools/gemini_warning_cleanup_helper cleanup-and-upload \
    --summary-file /path/to/your/summary_file.json \
    --upload
```
*(Note: Replace `/path/to/your/summary_file.json` with the actual path to the summary file. Use `--no-upload` if you do not want to upload to Gerrit yet, or match the user's preference. If running on a single repo, use `--only-repo relative/path` instead).*

The helper script will handle both:
*   Repos with unstaged changes (successful Gemini run): cleans and formats the combined changes.
*   Repos with clean working tree (failed-and-reverted or non-candidates): cleans and formats the original warning suppressions in `HEAD`.

## Notes

*   Reverting failed repositories to `HEAD` is **mandatory** before running `cleanup-and-upload` to ensure we don't attempt to format or commit broken Gemini changes.
